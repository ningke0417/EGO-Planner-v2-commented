# 任务1：固定墙6m，ours / Zhou / Quan

任务来源为 `/home/rise-lab/split-merge/对比实验.txt`。仅执行任务1：每个项目50轮，共150轮。
入口为 `scripts/run_comparison_benchmark.py`；不启用goal模式。

三项目依次为 `EGO-Planner-v2-commented`、`EGO-Planner-v2-official-baseline`、
`Swarm-Formation`。每轮使用其自身已编译的规划器和独立Noetic环境，启动前核对
`rospack find ego_planner`，每次运行前复核规划器及墙体生成器二进制哈希。
不修改三个项目的规划算法，也不向另外两个项目目录写入实验数据。

## 执行与自动停止

按 `ours第1轮 → Zhou第1轮 → Quan第1轮 → ours第2轮 → …` 串行运行，
每次使用新的 `--network none` 容器。这样既不会争抢同一轮CPU资源，也隔离了固定UDP通信端口。
容器结束后自动删除，录制结果写在本仓库 `bags/comparison_task01_…/` 中。
实际执行的监测脚本和式45计算模块会冻结到批次 `code/`，与正在编辑的源文件分开。

每轮完成后自动审计bag、导出位置表、计算指标、更新汇总。完成150轮后写入
`status.json` 的 `state=complete` 并退出；不会开始任务2及后续任务。
超时、未到达等有效飞行失败保留并计入分母，不用重试替换。
录制/通信/配置/审计错误会标记并停止，已录数据继续保留。

## 统一场景和指标

- 第一堵墙沿y方向长6m、厚0.5m，x=-2m，墙体高度[-0.1,3]m。
  第二堵墙x=6.5m、总长10m、中央开口1.8m，保持原配置。
- 八机2×4，邻接间距1m。起点中心(-6,0,1.5)，终点中心(10,0,1.5)，
  最大速度配置0.5m/s。RViz关闭。ours采用分布式并开启跨列换槽。
- 出发：任一机相对自身配置起点位移首次达到0.05m，采用该条Odometry时间戳。
  不使用速度阈值触发计时。
- 到达：八机各自距实际目标≤0.30m、速度≤0.15m/s，里程计不超过0.5s，持续1s。
  计时终点为稳定区间起点，不含1s确认时间。三项目统一采用几何/运动状态判定，
  不额外要求某一个项目独有的FSM或安全标志。
- 到达率：全员到达的有效轮次数/有效轮次数；到达成功的运行时间和平均耗时单列。
- 无碰撞到达率：全员到达且100Hz同步插值的整段飞行中，半径0.10m球体不与实际墙盒
  重叠、机间中心距不低于0.20m，且无非法里程计的轮次数/有效轮次数。
  保存最小机间中心距和球体到墙面的最小净空。此为采样球体模型，不是连续时间接触证明。
- 90s未出发记失败；出发后240s未全员到达记失败。里程计丢失超过5s为基础设施异常并停止。
- 规划器自身安全告警另外保存、计数；不以几何通过推断没有触发告警。

本批次重新使用统一监测脚本。旧单项目录制脚本的出发条件、碰撞半径、采样率或FSM门槛
不完全一致，因此旧结果不能直接替代本次三项目统一口径的统计。

## 论文式45

使用 `/home/rise-lab/split-merge/Robust.pdf` 第12页式(45)，保存论文SHA256。
对完整八机2×4模板做最优Sim(3)对齐，对残差平方和按三维质心弧长积分，除以
`s0 × 质心路径长度`，`s0=1`，单位m²。不除以8、不取平方根，不重新优化无人机编号对应。
ours的每个物理ID跟随其自身规划器实际应用槽位；Zhou和Quan跟随固定物理ID。
原始异步Odometry插值到共同100Hz时间轴，再用50Hz复核，检查是否完整覆盖飞行区间及数据间隙。

成功轮次计算出发至全员到达；失败且已出发轮次计算至失败截止，另行标明区间。
分别报告到达成功、无碰撞到达、全部已出发轮次的式45均值，不混淆完整和失败飞行区间。

## 文件和进度

- `status.json`：当前项目、轮次、容器名，最终为complete或stopped_error。
- `comparison_summary.csv/json`、`REPORT.md`：三个项目的当前及最终汇总。
- `all_trial_metrics.csv`：各轮指标、bag与位置表相对路径。
- `ours/run_001/`、`zhou/run_001/`、`quan/run_001/`等：独立轮次。
- `task01_ours_wall06m_8uav_run001.bag`等：LZ4压缩，项目/场景/墙长/轮次写入文件名。
- 每轮`drone_positions.csv`保留原始频率的物理ID、位置、速度、姿态和双时间戳。
- `metrics.json`、`formation_error_eq45.json`、`formation_error_timeseries.csv`：判定与误差。
- `ros_parameters.yaml`、`scene_geometry.json`、`scene_metadata.json`、规划/录包日志：复现与诊断。
- `config.json`、`supervisor.json`、`code/`：统一阈值、二进制/论文哈希、PID和冻结脚本。

bag保留里程计、控制指令、规划轨迹、规划耗时、心跳、编队协商、实际应用槽位、诊断和
实验事件/指标。不录点云、图像、占用栅格、地图MarkerArray及不断增长的可视化路径。
实际墙盒仅另存小型JSON；完整参数另存YAML。

启动新批次（会持续运行；后台启动应重定向日志并脱离终端会话）：

```bash
python3 -u scripts/run_comparison_benchmark.py \
  --runs 50 --output bags/comparison_task01_wall06m_50each_新时间戳
```

中断后可用原参数加`--resume`继续，已完成且审计通过的轮次不会重飞。
存在不完整轮次时会停止，需先保留并处理原始异常记录；不会覆盖文件。
